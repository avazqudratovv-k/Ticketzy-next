## Prompt 1 decisions
| # | Decision | Why | Open question |
|---|---|---|---|
| F14 | Palette values come from `tokens.json`, everything else in the MUI theme uses `var(--token)` | MUI computes hover/contrast colors from palette values and fails on `var()`; CSS variables make theme switching instant and SSR safe | Two sources must stay in step: `tokens.css` and `tokens.json` were copied together |
| F15 | Dark is always the default; the saved choice is applied by an inline script, no `prefers-color-scheme` | The prompt says dark by default | Follow the OS setting on first visit? |
| F16 | Media queries instead of the design's container queries on `.tz-app` | Simpler with MUI and SCSS; same breakpoints (480, 768, 1024) | Fine unless a layout is embedded in a narrower container |
| F17 | Design `tz-`/`pg-` class names reused in our SCSS, but `components.css` / `pages.css` are not imported | Prompt asks for MUI + SCSS; copying 85 KB of unused CSS would conflict with MUI | |
| F18 | Brand is the word Ticketzy with a Volt dot, not an image | Design: "There is no logo yet". The old `logoWhite.svg` is Nestar's | Real logo later |
| F19 | `LayoutAdmin` extended (not renamed): `withAdminLayout` and `withOrganizerLayout`; `LayoutHome` / `LayoutFull` re-export `LayoutBasic` | Kept the files and imports; the three duplicates were identical | Remove the aliases once the home page has its own layout |
| F20 | Signup role selector follows the design's two cards but uses `role="tab"` semantics | Prompt says tabs, design shows cards | |
| F21 | Organization name is sent as `memberNick`, full name as `memberFullName`; no phone | `MemberInput` has no organization field; `memberNick` is unique, so a taken name gives the "already used" error | Does the backend want a separate organization field? |
| F22 | After signup the member is signed in (the mutations return a token). A buyer goes to `returnTo` or home; an organizer sees the awaiting-approval panel and is signed in as PENDING | Prompt: PENDING organizers can log in | Not tested end to end (see below) |
| F23 | Login by role: ORGANIZER lands on `/organizer`, ADMIN on `/admin`, USER on `returnTo` or `/`; placeholder pages exist so the shell can be seen | Design text: organizers "land on their dashboard" | |
| F24 | Left out of the login design: "Forgot password?", "Keep me signed in", "Contact support" | No reset operation in the schema; the token always goes to localStorage as asked; there is no support page yet | |
| F25 | Dead links on purpose: Events, FAQ, Contact, About, Terms, Privacy, organizer/admin sub-pages, avatar-menu targets | Their pages come in later phases; the shell follows the design | They 404 until then |
| F26 | Server messages known to the UI ("Incorrect email or password!", account not verified, already used) are shown translated; any other server message is shown as sent | The API answers in English only and uses one code (`UNAUTHENTICATED`) for both login failures, so the message is the only way to tell them apart | If the backend text changes the mapping in `libs/errors.ts` must follow; better: distinct codes |
| F27 | A saved locale (`localStorage.locale`) redirects once on first load; `uz` is not auto-detected | Locale detection is off, the design wants the choice to persist | |
| F28 | The session is cleared only when `getMember` fails with UNAUTHENTICATED, FORBIDDEN or BAD_REQUEST; a network failure keeps the token | A backend restart should not sign everyone out | |
| F29 | Chat WebSocket: nothing built. `NEXT_PUBLIC_API_WS_URL` is still unused; the client will send the token in a first `auth` message | Prompt | |
| F30 | Old files are left unused instead of deleted (list in FRONTEND_COMPLETED_TASKS.md) | A bulk delete was blocked by the permission system | Delete them with `git rm` |
| F31 | The shell shows nothing until the member is allowed in (no skeleton) | Avoids a flash of dashboard content for the wrong role | |

## Prompt 2 decisions
| # | Decision | Why | Open question |
|---|---|---|---|
| F32 | Data is fetched in the browser with Apollo; only the SEO tags come from `getServerSideProps` (anonymous plain `fetch`) | The Apollo client has no link on the server and the member's token lives in `localStorage`; the like state and view count need the token | If a page must be indexed with its full text, add a server Apollo link |
| F33 | The event detail waits for the stored session (`authReadyVar`) before its first request | The first request then carries the token, so the view is recorded once and `meLiked` is right | The page shows a skeleton until the session check ends |
| F34 | A hidden event (draft, pending, cancelled, ended for visitors) shows "Event not found" | The API answers `NO_DATA_FOUND` for all of them, so the page cannot tell them apart | Ask the backend to return CANCELLED and ENDED events publicly (read-only) if buyers should see them |
| F35 | Text search is sent as is. When the text equals a category name in the active language (or `comedy`, `concert`, `football`), the empty state offers "Show all Comedy events" | The API only searches `eventTitle`; "comedy" finds nothing | Backend could search translations, category and venue |
| F36 | Category filter has four slugs: `concert`, `football`, `comedy`, `other` (other = SPORT, THEATER, CONFERENCE, FESTIVAL, OTHER) | The design shows four filters; the enum has eight values | |
| F37 | Date filter uses Seoul midnight boundaries (`+09:00`) | Venues default to Asia/Seoul and the API takes absolute times | Per-venue boundaries are not possible in one query |
| F38 | Page size 12 with numbered pagination (compact "Page 2 of 3" below 768px); no "Show more" | Design allows either; numbered pages keep the page in the URL | |
| F39 | Left out of the browse design: "Hide sold-out events" and the top-bar search box | The list API has no sold-out filter, and a second search field would duplicate the one on `/events` | |
| F40 | Cards have no "Sold out" badge | `getEvents` does not return ticket stock; the detail page derives it from `getTicketTypes` | Backend could expose a `soldOut` flag |
| F41 | Detail "Select seats" button reads "Select tickets" for GENERAL events and is disabled for cancelled, ended, sold out and not-yet-on-sale events, with the reason as its label | Matches the design's separate general-admission flow; the prompt says "Select seats" for the primary case | Use "Select seats" everywhere if preferred |
| F42 | Refund line is hidden for cancelled and ended events; the cancelled banner says orders are refunded automatically | The 23:59 rule is meaningless for them | |
| F43 | `cancelReason` is shown when the API sends it (owner and admins only) | It is the only reason text available | |
| F44 | "Open in maps" is a Google Maps search link built from the venue name and address; no embedded map | `venueCoordinates` order is not documented and an iframe adds a third-party request | Embed later |
| F45 | Uzbek dates are composed by hand (`Yakshanba, 8-noyabr`); other languages use `Intl` | Chrome and Node have no Uzbek date data (Intl prints "M11 8, Sun") | Re-check when ICU gets full `uz` |
| F46 | Prices use `Intl` with the ticket's currency and `narrowSymbol` (₩ in all languages, grouping per locale: `33 000 ₩` in Russian) | The design's table shows ₩65,000 for Korean only | |
| F47 | Title, description and image in the SEO tags come from the active language with the EN fallback; the server query is anonymous | Same rule as the page; hidden events get a generic title and `noindex` | |
| F48 | Comments: delete is `updateComment` with status DELETE, confirmed inline (no browser dialog); 1000 characters client limit; own comments only | There is no member-level remove operation; the length limit is not in the schema | Check the backend limit |
| F49 | The like button redirects logged-out visitors to login with `returnTo` | Prompt: like for logged-in users | |
| F50 | Organizer page rejects members that are not ORGANIZER and shows the first 12 upcoming events with a "N more not shown" line | `getMember` answers for any ACTIVE member | Add a "load more" when an organizer has many events |
| F51 | Category links in the top bar appear from 1024px; the 768px bar kept wrapping the auth buttons | Not enough room | A burger menu up to 1023px would keep them reachable |
| F52 | Avatar-menu targets (My tickets, Orders, Settings) were left as they are (F25) | Their pages come in later phases | |
| F53 | `reloadOnPrerender` is on in development in `next-i18next.config.js` | Locale JSON edits showed stale keys until the dev server restarted | |
| F54 | Seats page `/events/[id]/seats` is a placeholder with a back link | Next prompt | |

## Prompt 3 decisions
| # | Decision | Why | Open question |
|---|---|---|---|
| F55 | Comment limit is 500; the "Show all <category> events" empty-state button is removed (F35 no longer applies) | Backend DECISIONS #65 and #66 | |
| F56 | A declined payment (`simulate: FAILURE`) makes the backend fail the order and release the seats, so "retry" is a new `holdSeats` plus `createCheckout` for the same seats (or quantities), not a second `payOrder`. The seats are kept per order in sessionStorage; if that is gone after a reload the retry button sends the buyer back to the seat picker | The old order cannot be paid again (`ORDER_NOT_PAYABLE`) | The retry can lose a seat to someone else in between; the page then says so |
| F57 | Continue holds and creates the order in one step (no separate "held" screen). The hold countdown on the seat page shows only for a hold that exists (restored after a reload, or when order creation failed) | The prompt wants the countdown to continue in checkout; a 30 s window leaves no time for a middle step | |
| F58 | Server state is the truth after a reload: my held seats come from `getEventSeatMap` (`mine`), a pending order from `getMyOrders(PENDING_PAYMENT)`. On the seat page a pending order shows a banner (resume payment or choose other seats) and blocks new picks; "choose other seats" cancels the order first | Back from checkout must not trap the buyer, and a second hold would silently kill the first order | |
| F59 | Clock skew comes only from `holdSeats.serverTime` (midpoint of the request) and is kept in sessionStorage. A tab that never called `holdSeats` assumes no skew | No other operation returns the server time, and `Date` is not readable cross-origin | Add `serverTime` to `getOrder` or the seat map |
| F60 | The checkout page calls the hold "lost" when a held seat's `holdExpiresAt` differs from the order's `expiresAt` by more than 1 s, or the held seat count differs | `holdSeats` gives every seat of a call the same deadline and the order takes the earliest, so a later deadline means a newer hold (another tab). Counting seats alone missed a replacement hold | |
| F61 | Leaving inside the app releases the hold (`releaseSeats`) on the seat page and cancels the pending order (`cancelPendingOrder`) on checkout, through the router's `routeChangeStart`. A reload or closing the tab does NOT release | A reload must restore the state (prompt), and a tab close cannot be told apart from a reload; the 30 s hold frees itself | Use `pagehide` plus `sendBeacon` if early release on close matters |
| F62 | "Change seats" on checkout cancels the order first, then opens the seat page | Otherwise the seat page would restore the seats as mine and then flash a "released" message | |
| F63 | Section geometry: seat pitch 13 / 16 / 21 px for COMPACT / NORMAL / WIDE; section `x`, `y` are the centre; rotation is clockwise degrees; row 1 is the row nearest the stage (top at rotation 0, as in the design's seat map editor); seat 1 on the left. The view fits the bounding box of all sections, not the fixed 1000x700 (a rotated section near the edge would be cut off). A "Stage" bar is drawn at the top unless the venue has a STANDING area (the floor is the stage) | The layout has no stage field and no pitch field | Backend could send a stage position and seat pitch |
| F64 | Tier colours are assigned in order of first appearance (three design tokens `--tier-1..3`, then fixed extras); tier names in the legend come from the ticket type of that `tierKey` | `tier-*` colours live only in the design's pages.css, so they were added to `seats.scss` | |
| F65 | Wheel zoom is always on over the map (plain wheel, not Ctrl+wheel) | The prompt lists the wheel; the page still scrolls when the pointer is off the map | Ctrl+wheel only, if page scrolling over the map bothers people |
| F66 | The map is an SVG with seats `aria-hidden` for pointer use; the accessible way is the section list plus a grid of real seat buttons for the chosen section | 500+ focusable SVG seats are unusable with a keyboard | |
| F67 | A seated tier whose ticket type is paused, sold out, outside its sale window or missing shows its seats as locked (not selectable) | `createCheckout` would refuse them with a generic "not allowed" | |
| F68 | GENERAL: quantity per ticket type, limit = min(`maxPerOrder`, remaining). No total cap is applied (the backend has none for quantities) and `maxSeatsPerOrder` is not used. The order reserves stock and expires after the same hold seconds | Backend DECISIONS #46 | The prompt's "do not hardcode 8" is met by reading `getSeatConfig` for seats only |
| F69 | Unknown or untranslated server messages become one generic translated error; known messages are mapped in `libs/seats/errors.ts` only. `Not Allowed Request!` (ended, sold out, closed, inactive account all use it) gets a cautious "could not be done right now" text; the hold-limit message does not repeat the number | Messages carry no codes | Ask for codes, then replace the map keys |
| F70 | The first seat-map request runs even in a hidden tab; polling still pauses while hidden | A page opened in a background tab otherwise stays on "Loading seats" until focus | |
| F71 | The session is watched by the token's own expiry every 5 s on the seat and checkout pages (`useSessionWatch`); an expired token clears the session and the page guard redirects to login with returnTo | `getEventSeatMap` accepts a bad token as anonymous, so the poll never reports an auth error | |
| F72 | Confirmation shows seats from `getMyTickets` (first 50 upcoming, filtered by order) with section names from the seat map; `Order` has no seat coordinates | There is no orderId filter on tickets | Add `seatData` to `Order`, or an order filter on `getMyTickets` |
| F73 | `/orders` is a placeholder; `/orders/[orderId]/confirmation` is the confirmation route; `/checkout/[orderId]` the checkout route | Next prompt builds the order history | |
| F74 | The demo payment shows disabled sample card fields and never reads input; "Simulate a failed payment" is a visible checkbox | The prompt: no real card data, visible demo failure | |
| F75 | The seat picker is a fixed bottom sheet below 1024 px; the page gets extra bottom padding for it | The prompt asks for a mobile summary sheet | The sheet covers alerts while it is open |
| F76 | The service fee line says "Included" because the backend takes the commission from the organizer (`totalAmount = subtotal`, backend DECISIONS #47) | | |
| F77 | Account routes follow the design (`/tickets`, `/orders`, `/notifications`, `/settings`), not a single `/account/*` tree; Likes and Following live under `/account/saved` and `/account/following` | The design's sidebar and the existing avatar-menu links already point there; `/account/*` already holds login and signup | `/account` itself has no page |
| F78 | `getOrder` returns `eventData: null`, so the order detail takes the event from the order's tickets, or from `getMyOrders` (limit 100) for unpaid orders. `getEvent` is not used | `getEvent` records a view for the member and hides cancelled events | Backend: join `eventData` in `getOrder`; then this fallback can go |
| F79 | Venues of orders and tickets are loaded with aliased `getVenue(venueId)` calls in one request (`useVenues`) | `eventData.venueData` is always null, and the venue zone is needed for dates | Backend: join `venueData` in orders and tickets |
| F80 | Notification titles are translated by `notificationType` in the client; descriptions are shown as sent (they are data: order number, event title, comment), except the 'n order(s) refunded, m failed' sentence, which is rebuilt. ORDER_PAID reads 'Payment received' for buyers and 'New ticket sale' for organizers and admins | The server sends English only; one type can reach two roles | Titles of organizer types are generic; their server titles may carry more text |
| F81 | Refund eligibility is only what `getRefundQuote` and `requestRefund` answer. 'Already refunded' is inferred when the returned `refundedAt` is more than 5 s older than the click (the backend returns a refunded order unchanged); this uses the client clock | The backend gives no flag for it | A skewed clock can show 'done' instead of 'already refunded'; harmless |
| F82 | Not built because the backend has no operation: partial refunds, refund by ticket, reason list, download PDF, change password, delete account, notification preferences, 'days left' on the deadline | The prompt: do not guess operations; no password reset | 'Days left' could be added from the quote deadline |
| F83 | EXPIRED is a label for a VALID ticket whose event has ended (`eventStatus ENDED` or `endAt` past). The server never sets it and it decides nothing | The prompt asks for a clear expired state | Uses the client clock |
| F84 | The ticket code is shown under the QR as a reference, not as a door fallback | The backend check-in takes the QR token, not the code (backend DECISIONS #52) | Design text says staff can read the code; changed to avoid a false promise |
| F85 | The QR is always black on white, also in the dark theme, and the full-screen scan view is white with black text | Scanner contrast | No screen-brightness API in browsers; the page only advises |
| F86 | Only the header bell polls `getUnreadNotificationCount`; the sidebar badge and the page read the shared cache | One poller instead of three | Polling stops while the tab is hidden and runs once on return |
| F87 | Avatar upload: PNG or JPG, 5 MB on the client (server limit 15 MB; the server checks the real type by magic bytes). Nickname 3 to 12 and full name 3 to 100 characters, as the DTO says; phone has no server rule, the client only checks digits and length | Friendlier limit; avoid server round trips for known rules | Phone format check is a guess |
| F88 | The refund and Request buttons use a `tz-btn-danger` class because the MUI theme paints every `contained` button with the accent colour | Design says refund is a danger action | Could be fixed in the theme with a `color=error` variant |
| F89 | The unused `orders.*` placeholder strings were removed from `checkout.json` | The placeholder page is gone | None |
| F90 | On phones the header controls were tightened (gap 0 below 480 px); with the bell added, the menu button had been pushed off screen | Found at 390 px | The header is crowded at 390 px; the theme toggle could move into the menu |
| F91 | `yarn build` was run in a scratch copy (no `.next` shared) because a dev server owns `.next` on port 3000; the browser tests ran on that real dev server | A build over a running dev server breaks it | None |
